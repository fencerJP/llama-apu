# AMD Silicon Architecture & Hardware Support Matrix

This document defines the silicon tier matrix, hardware architectural differences, and scheduling strategies implemented by the **AMD Ryzen AI APU Drop-In llama.cpp Runtime**.

---

## 2. Why AMD XDNA 1 Silicon (Phoenix / Hawk Point) is Dropped

Preceding APU generations featuring **AMD XDNA 1** silicon (Ryzen 7040 "Phoenix" and Ryzen 8040 "Hawk Point") are **strictly deprecated and unsupported** in this runtime.

### Technical Rationale:
1. **Lack of Hardware BlockFP16 Arithmetic**:
   - XDNA 1 tiles (AIE-ML) only support INT8, INT16, and FP32 emulation. They lack the native hardware mathematical instructions for BlockFP16/FP16 matrix accumulation present in AIE2P.
   - Running modern LLM quantizations (such as Q4_0, Q8_0, or BlockFP16) on XDNA 1 requires software emulation passes that degrade decode throughput below CPU AVX-512 speeds.
2. **Compute & Tile Array Density**:
   - XDNA 1 tops out at 10 to 16 TOPS across 20 tiles.
   - XDNA 2 delivers 50 to 55 TOPS across 32 tiles—a 3.5x to 5x throughput leap that makes NPU decode genuinely superior to CPU decode.
3. **Linux Kernel Driver & Runtime Stack Divergence**:
   - AMD XDNA 2 utilizes the modern upstream DRM Accel driver (`amdxdna.ko`) supporting standard Linux `dma-buf` cross-device importing and DRM timeline synchronization objects (`drm_syncobj`).
   - XDNA 1 required legacy out-of-tree staging drivers with incompatible memory pinning APIs that broke true zero-copy unified memory handoffs.

*If you attempt to run on an XDNA 1 system, `apu-doctor` and `llama-cli` will report an explicit `UnsupportedSiliconError` and gracefully recommend CPU AVX-512 execution.*

## 3. Heterogeneous Zero-Copy Memory Architecture

AMD Ryzen AI APUs feature a **Unified Memory Architecture (UMA)** where the CPU, iGPU, and NPU all reside on the same physical silicon substrate and share the same physical LPDDR5X memory pool.

Traditional inference stacks (like upstream llama.cpp with split backends) perform redundant host-side `memcpy` operations:
```text
Traditional Path (High Latency & Bandwidth Waste):
  [Prompt] -> Host CPU RAM -> [memcpy] -> iGPU VRAM (Prefill)
           -> [memcpy] -> Host CPU RAM (KV Cache)
           -> [memcpy] -> NPU Memory (Decode)
```

The **zero-copy-model-runner** pipeline bypasses the host entirely:
```text
Zero-Copy APU Pipeline:
  [AMDGPU GEM Buffer] <=== Linux dma-buf export/import ===> [AMDXDNA NPU Buffer]
           |                                                        ^
           | (Prefill writes K, V)                                  | (Decode reads K, V)
           +-------------------- Shared Physical UMA ---------------+
```

### Invariants:
1. **Physical Zero-Copy**: The attention Key and Value matrices generated by the RDNA 3.5 iGPU are written directly into physical pages backed by a `dma-buf` handle. The XDNA 2 NPU maps this exact physical address space.
2. **Timeline Fence Synchronization**: Transition from prefill to decode is signaled via `drm_syncobj` timeline points. The CPU enters sleep state rather than burning power on a busy-wait spinloop.
3. **Cache Line Alignment**: All tensor offsets and DMA buffers strictly adhere to 64-byte boundaries, matching Zen 5 and AIE2P memory controller transaction sizes.

## 4. Architectural Scheduling & Routing Strategy

The runtime automatically inspects the APU model at startup and applies the optimal hardware scheduling:

### Standard APUs (Strix Point, Gorgon Point, Krackan Point)
- **Prefill (Compute-Bound)**: Routed to the **RDNA 3.5 iGPU**. High compute density (up to 16 CUs) calculates prompt attention quickly.
- **Decode (Memory-Bound)**: Routed to the **XDNA 2 NPU**. The 32 AIE2P tiles stream weights and update the KV cache with maximum energy efficiency and dedicated tile scratchpad memory.
- **Sampling**: Routed to **Zen 5 AVX-512**. AVX-512 SIMD provides sub-microsecond categorical sampling and temperature scaling without kernel launch overhead.

### AMD Strix Halo (Ryzen AI MAX+ 395)
- Strix Halo features a massive **40 CU RDNA 3.5 GPU** with **273 GB/s 256-bit memory bandwidth**.
- On Strix Halo, the default policy automatically routes both prefill and decode to the iGPU to capitalize on the 273 GB/s bandwidth, while keeping the NPU ready for multi-tenant background tasks.

## 5. Manual Routing Overrides

Users can override the automatic silicon scheduler at any time via CLI flags:

| Flag | Effect | Use Case |
| :--- | :--- | :--- |
| `--gpu-based` | Forces Prefill and Decode to RDNA 3.5 iGPU | Maximum throughput on systems with high memory bandwidth. |
| `--cpu-based` | Forces all stages to Zen 5 AVX-512 | Diagnostic verification, fallback, or when running headless without GPU drivers. |
| `--npu-based` | Forces maximum possible phases to XDNA 2 NPU | Maximum battery life and minimal thermal power on mobile laptops. |
| `--tokenize <cpu\|gpu\|npu>` | Overrides tokenization engine | Custom BPE tokenization backend. |
| `--prefill <cpu\|gpu\|npu>` | Overrides prefill engine | Force CPU prefill or test NPU prefill. |
| `--decode <cpu\|gpu\|npu>` | Overrides decode engine | Force CPU or GPU decode. |
| `--sample <cpu\|gpu\|npu>` | Overrides sampling engine | Benchmark sampler algorithms. |
